# 深挖现有客户端后的增量兼容性

客户端基线：`bd9262397208c509ea97af61f0d44621ef25611c`。实现以
Console `v0.2.35`、Server `v0.2.39` 为起点，不修改当前客户端仓库。

用户后续明确允许用户在自己的 fork 中替换配置验签公钥并自行构建客户端。
Console 因此新增隔离的“自有签名客户端”feature，默认关闭；不是官方签名或
商业授权替代，也不是客户端构建服务。

## 本轮范围与验收

1. hbbs 登录门禁：启用 MUST_LOGIN 时，普通及切换的打洞、中继协调请求只接受
   配置密钥验证通过的账户 JWT，或现有目标绑定的切换授权；密钥为空不能接受
   任意非空 token。关闭 MUST_LOGIN 时保留既有行为；不要求标准客户端未发送的
   RequestRelay licence_key，不增加实时 ACL 或账户撤销系统。
2. hbbs 传输提示：在已有消息字段间保留 IPv6 地址；将客户端强制中继请求及
   服务端 ALWAYS_USE_RELAY 设置传给被控端。无提示时保持既有值，不升级子模块。
3. 客户端目录：按请求的 users.status / peers.status 在分页之前过滤，保持原有
   可见性边界，不把账户禁用等同于设备禁用；返回真实设备备注和状态。
4. 集中策略：增加已有 Config 消费路径的 KCP 拥塞控制、Android 软件编码半分辨率、
   Windows SYSTEM 服务录制目录。管理界面说明平台限制和作用，不伪装为 WebRTC
   LocalConfig 下发，不改变默认策略或无策略设备。

各项须有聚焦回归测试，完成后运行两仓 Rust 测试、前端测试及构建，并检查最终
diff 中现有路径的改动必要性。不顺带增加容量配额、品牌化客户端、控制角色系统、
即时连接 ACL，或假报浏览器远程会话/完整 Pro 等价能力。

## 自有签名客户端 feature

- 设置页保留一个显式开关；关闭时专属菜单、品牌和高级配置选项全部隐藏，直接
  访问功能页也不展示表单，后端拒绝生成密钥/签名导出等操作。
- 密钥配置、品牌外观、预置策略、构建与文档按类别组织，复用现有管理界面样式。
- 设置中生成或导入 Ed25519 密钥对，验证配对；私钥仅在服务端受限文件持久化，
  不回显、不记录日志、不放入 custom.txt、公钥补丁或浏览器存储。
- 导出 `base64(signature || JSON)` 的 custom.txt，JSON严格匹配客户端
  `read_custom_client`；支持 app-name、已证实的品牌字符串、default-settings
  和 override-settings。签名配置可设置 LocalConfig，这与心跳策略不同。
- 内置中英文文档，准确列出 fork 替换公钥、自行构建、custom.txt 放置路径、
  logo与平台图标差异、更新签名独立性、服务端能力和未实现边界。
- 不修改现有默认行为；不把启用 UI feature 视为连接 ACL 或商业授权。
- 验收包括后端开关门禁、权限、错误密钥/签名、私钥脱敏、受限文件权限、配置
  真实验签；前端开关前后菜单和直达路由、双语、窄屏与键盘可用性。
