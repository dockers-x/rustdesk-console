# v0.2.39

Console 全 workspace Rust 审核修复版，沿用 v0.2.38 的自有签名客户端与一次性密钥备份能力。

## 安全与兼容性

- 普通用户的客户端 CLI 指派仅允许自己，拒绝越权指派用户、设备组、策略和改写他人设备；管理员及部署 token 保留显式授权流程。
- 部署 token 额度在设备写入前原子领取，防止一次性 token 被并发超用；领取后部署失败也计入使用次数，不再承诺只统计成功部署。
- 强制改密状态同样应用于客户端 bearer 与 CLI 接口，不再仅限制后台 API。
- OAuth 绑定验证流程完成状态及已有身份；登录只消费正确 action；上游 HTTP 错误、缺失或无效用户 id 不再退化为共同身份。文案以 JSON 字符串生成 JavaScript。
- OAuth 成功/失败网页中的文案按内联脚本上下文安全编码，包含引号、换行或 script 结束标记的错误文字不再破坏页面脚本。
- 旧地址簿标签同步限定在当前集合，不再删除同一用户其他集合的标签。

## 可靠性

- 配置使用随机、独占创建的临时文件，Unix 创建时即0600；保存前验证 YAML，避免多行块被写坏。原有权限和成功后更新运行设置的顺序保留。
- logout 和批量地址簿写入失败返回真实错误，不再报告成功；批量操作仍不是全有或全无事务。
- 验证码生成回收过期条目并限制总量；超大 JWT 过期配置在启动时明确拒绝；非法诊断端口不再算术溢出。
- 登录审计正确关联本次 token 记录。

## 升级边界

无需数据库迁移，不修改 hbbs/hbbr 协议或客户端代码。自有签名功能仍默认关闭，已有独立 feature 文件和密钥无需重新生成。若旧配置使用多行 YAML 且设置保存会破坏块结构，现在保存会失败并保留原配置，而不是宣告成功后留下无效文件。

审核范围、限制与回归面见 `docs/2026-10-29-workspace-rust-review.md`。不声称支持完整官方 Pro 授权、在线客户端构建或实时 ACL。
