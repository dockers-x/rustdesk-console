# 安全升级与客户端兼容性

本次修改针对 Console API 与配套 hbbs 的权限边界，不修改 RustDesk 客户端。它不能证明此前异常事件的原因，也不会自动终止已经建立的远控会话。

## 升级顺序

1. 备份 Console 数据库、配置和密钥，检查现有设备归属、共享规则、地址簿和策略是否可信。
2. 升级 Console v0.2.42，再升级配套 Server v0.2.44。
3. 为 hbbs 设置 `MUST_LOGIN=Y`，设置与 Console 相同的 `RUSTDESK_API_JWT_KEY`，并设置 `RUSTDESK_API_RUSTDESK_API_SERVER` 为该 Console 地址。远程地址必须使用 HTTPS；HTTP 仅允许显式的 loopback IP，例如同网络命名空间的 `http://127.0.0.1:21114`。容器跨网络命名空间部署应使用 HTTPS 地址。
4. 在隔离测试设备上验证管理员和设备所有者可以发起连接，仅有地址簿共享权限的用户及无关账号被拒绝。

启用强制登录后，每个打洞和中继协调请求都会查询 Console 的当前会话和目标权限。未配置地址、连接失败、超时、无效响应、账号禁用、token 撤销或目标设备禁用均拒绝。签名且绑定目标的短期 Switch Sides 授权沿用原有路径。

保持 `MUST_LOGIN=N` 的旧部署继续允许未登录连接，不提供账号到目标设备的连接隔离。IP 直连、已经建立的会话和直接访问独立中继的流量不由这项 hbbs 检查覆盖；应配合客户端远控密码、人工确认和网络访问限制。

## 设备归属与共享

管理员可访问已登记且启用的设备。普通用户仅可访问自己拥有的启用设备，所有者账号也必须启用。地址簿及其共享规则管理目录可见性，不授予设备连接权限；手动添加设备 ID 或编辑共享集合也不会取得连接授权。

设备归属通过管理员操作或管理员发放的部署 token 建立。普通账号登录、退出以及提交设备 UUID 都不会改变归属；普通账号不能抢占未归属设备或自行登记一个任意 ID 来获得连接授权。未登记或未归属的设备需要先由管理员确认。

## 原版客户端上报

当前客户端源码中，`src/hbbs_http/sync.rs` 的 heartbeat/sysinfo 和 `src/server/connection.rs` 的连接审计不带账号凭据。客户端 ID、UUID 和 nonce 也不是设备身份证明。

Console v0.2.44 撤回 v0.2.42 引入的默认拦截，恢复接收原版客户端的匿名 heartbeat、sysinfo 和审计上报，在线状态与集中策略同步无需客户端额外提供账号凭据；账号登录、地址簿和 hbbs 连接授权仍是独立路径。

以下为默认配置，建议仅通过可信网络或受控入口接收上报：

```yaml
security:
  allow-legacy-device-reports: true
```

对应环境变量为 `RUSTDESK_API_SECURITY_ALLOW_LEGACY_DEVICE_REPORTS=true`。如旧部署的配置文件或环境变量显式设为 `false`，需删除该覆盖或改为 `true`，并重启 Console；升级不会覆盖管理员的显式设置。需要拒绝匿名上报的部署仍可显式设为 `false`，但原版客户端届时无法更新在线状态、同步策略或提交这些审计。

此选项接受可伪造的客户端上报，不提供可信设备认证或不可抵赖审计。即使开启，sysinfo 预设字段也不能改变用户归属、设备分组、策略或地址簿；已有设备的 UUID 不匹配会被拒绝。新发现设备只能作为未归属库存。

## 注册与登录防护

管理员可在“系统设置 → 安全”修改“允许用户注册”，保存后立即生效，并保存在数据库。未保存过时沿用 `app.register`；关闭后阻止密码注册和 OAuth 新账号自动创建，已有账号登录和已验证邮箱匹配绑定仍可使用。LDAP 属于管理员配置的目录接入，不由此开关关闭。

登录 IP 默认使用实际连接地址。只有 `gin.trust-proxy` 中列出的代理 IP/CIDR 才能提供转发地址，多个值用逗号分隔，并从右侧跳过可信代理。不要配置可被外部客户端绕过的代理入口。

可信设备 ID/UUID 不再豁免登录设备验证；已要求设备验证的账号每次仍须完成验证码。已有登录 token 不会因升级自动撤销，应主动撤销异常会话并更换受影响的凭据。

录像上传、分片写入和删除要求已登录的管理员凭据，兼容上报开关不会开放这些操作。当前原版客户端的自动录像上传开关默认关闭，不能据此声称原版自动上传已可用。

登录验证码挑战每个账号在 10 分钟内最多创建 5 个，限制在数据库中按账号执行；同一挑战提交一次后即消耗，错误后须重新发起登录。切换 IP 或重新申请 secret 不会清空账号额度。

WebClient 共享链接在每次取回凭据时复查创建者和目标设备是否启用、设备是否仍归其管理。已经获取的远控密码无法通过撤销链接收回，应在被控端更换密码。强制登录模式不会为匿名共享链接绕过设备连接授权。

当前原版客户端控制端的 `send_note` 仅发送设备 ID、session_id 和备注，不带 UUID 或账号凭据。此路径即使开启兼容上报也会被拒绝；不能宣称所有原版审计备注都已恢复。已登录且有设备权限的客户端可使用原有 `/api/audit` 备注接口。

### 原版客户端的远控设备信任

用 RustDesk 1.5.3 的客户端源码核对过以下流程。

1. 在**被控端**的「设置 → 安全」启用双重验证和「启用可信设备」，并配置固定密码。
2. 在**控制端**用该固定密码连接。在被控端的 TOTP 对话框勾选「信任此设备」，输入正确的验证码并完成连接。临时密码、点按同意和切换会话等流程无法建立这项信任。
3. 后续从同一个控制端连接同一被控端时，控制端会出示本地保存的信任凭据。凭据有效时跳过被控端 TOTP，仍需通过固定密码验证。可在被控端「管理可信设备」查看、续期或删除记录。凭据过期、被撤销或控制端的本地凭据丢失后，重新走第 2 步。

被控端签发并管理远控凭据。「我的设备」中的 ID 和 UUID 用于标识设备。原版客户端会过滤心跳里的可信设备开关和期限设置，请在被控客户端本地配置。Console 网页登录可在 HTTPS 下完成验证后勾选「信任此浏览器 30 天」。

## Console v0.2.49 二次验证

已绑定 TOTP 的管理员继续在登录时验证。未绑定的管理员在账号和全局策略允许时可以进入 Console，页面显示绑定提醒，点击「本次跳过」后可继续使用，下次登录时会再次显示。主动强制的账号仍进入受限绑定流程。此放宽只适用于新签发的 Console 会话。原生客户端和 Web SSO 继续执行二次验证要求。修改密码或绑定、重置 TOTP 后，既有会话和认证挑战同时撤销。

管理操作可在 Console 审计页查询。数据库审计清理默认关闭，启用后可预览并手动分批清理。

在「用户 → 编辑 → 重置密码」中，管理员可手动设置新密码，也可通过已启用的 SMTP 向用户已保存的邮箱发送一次性重置口令。收件人在登录页选择「找回密码 → 使用邮件重置口令」，在 15 分钟内使用完整口令。密码重置成功后，原有会话和待用认证挑战会被撤销。重置管理员账号要求操作者已通过 TOTP，LDAP 账号的密码由目录服务管理。

## Console v0.2.45 认证和审计

- v0.2.45 要求管理员绑定 TOTP，原有管理员会话须重新登录。新版登录规则见上一节。
- 启用全局 TOTP 后，未绑定的普通账号也须在 Console 完成绑定。管理端 OIDC 支持本地补验。stock RustDesk 的 OIDC 轮询只处理 access token，涉及本地二次验证时，请使用密码登录，或在启用 Web SSO 的部署中从已完成二次验证的 Console 会话授权。Web SSO 审批依赖对应会话仍然有效。
- 管理会话有效期上限为签发后 12 小时，Web SSO 派生会话沿用授权会话的有效期上限。会话管理接口只返回会话元数据。登录接口保持原有客户端响应协议。
- 密码登录在两个入口共享单进程限流，每个 60 秒固定窗口最多接受同一账号 10 次、同一来源 60 次密码校验。多副本部署在受控入口额外实施跨实例限流。普通设备的兼容上报继续使用现有策略。
- 安全事件使用 stdout 上的 JSON，目标为 `security_audit`，适合使用容器日志驱动或日志代理归集。用 `request_id` 关联反代记录，用 `session_id` 关联签发与后续请求。认证结果以 `outcome` 和 `reason` 为准，管理端 HTTP 200 仍可能携带业务拒绝。将日志归集到 Console 管理权限之外，并按部署需要配置保留期。
- 反代日志记录上游响应的 `X-Request-Id`。Nginx 可使用 `$upstream_http_x_request_id` 配合 `$uri`。公网入口应覆盖来自不可信请求的转发头，Console 的 `gin.trust-proxy` 只包含实际代理地址。反代和 Console 同在 Docker 网络时取消宿主机端口发布。需要内网直连时将样例中的 `RUSTDESK_CONSOLE_BIND_IP` 指向受控的内网地址。
- 按镜像 digest 固定部署，保留镜像标签 `org.opencontainers.image.revision`。Console 启动审计包含源码 revision，加载外部 WebClient v2 时还会记录 `data/web.zip` 的 SHA-256。安装外部 ZIP 前从信任的渠道取得并核对归档，在 Console 停止时替换。在维护窗口完成首次管理账号初始化及 TOTP 绑定。

如果唯一管理员丢失验证器，持有 Console 数据库访问权的主机管理员可执行
`rustdesk-console -c ./conf/config.yaml reset-totp <用户 ID>` 来撤销原会话并开始重新绑定。
请在受控入口完成恢复，保留本地 CLI 输出的安全事件。

开发者 API 密钥有独立的 scope、到期和撤销策略。处置账号失陷时，在检查和撤销交互会话之外，也要检查该账号签发的密钥。
