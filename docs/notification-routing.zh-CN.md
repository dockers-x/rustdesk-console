# 设备上线与下线通知

在 Console 的「通知路由」新建一条规则，选择渠道和事件。移动推送默认勾选「上线」。可按 RustDesk 设备 ID 或设备组筛选。同一设备与事件可以匹配多条规则，每条规则独立投递。

| 渠道 | 配置 |
| --- | --- |
| ntfy | 实例地址、Topic、可选的访问令牌。可用 `https://ntfy.sh` 或自托管实例。 |
| Bark | Bark 服务地址和设备 Key。可用 `https://api.day.app` 或自托管实例。 |
| Server 酱 | 填入 SendKey 后自动识别 Server 酱³ 或 Turbo。 |
| Webhook | 接收地址和可选的 HMAC 签名密钥。 |

Server 酱³ 的 SendKey 用于 **Server 酱 App 推送**。Turbo 的 SendKey 用于 **微信推送**。需要两处都收到时，分别保存一条 Server 酱规则。 [Server 酱³ 获取 SendKey](https://sc3.ft07.com/sendkey) · [Server 酱 Turbo 获取 SendKey](https://sct.ftqq.com/sendkey)

每种渠道都可以在创建或编辑时点击「发送测试」，已保存的规则也可以从列表测试。草稿测试会尝试发送通知并记录结果，配置仍需手动保存。发送失败可在弹窗或投递记录中查看原因。

## 模板管理

先在「模板管理」创建模板，再在规则中选择。修改模板会影响所有使用该模板的规则。仍被引用的模板必须在规则中解除关联后才能删除。规则可以随时切回内置模板。

标题和正文都可以编辑普通文字。使用变量选择器插入设备 ID、设备名、主机名、平台、系统用户名、设备组、事件类型、当前状态、先前状态、事件时间和最近在线时间。每个变量在编辑器中显示为可移除的标记。手动输入的花括号文字会原样发送。

移动推送以模板渲染结果为标题和正文。Webhook 保留原有事件结构与签名，选用模板时会额外携带 `notification.title` 和 `notification.body`。使用内置模板时，移动推送仅包含设备名称、ID 和当前状态。测试使用示例设备字段。

## 投递和重试

- 设备首次被观察到在线，或从离线恢复时，会产生上线事件。持续心跳不会重复发送。离线判断沿用 Console 的 90 秒在线窗口。原版客户端的上报兼容策略继续生效。
- 进入队列时保存各规则的渲染结果。后续修改模板会影响新事件，待投递消息继续使用当时的模板内容。禁用或更换通知目的地会终止该目的地的未开始投递。
- 投递互相独立。对可重试的失败最多尝试三次。对方收到消息但响应丢失时，重试可能产生重复。Webhook 消费方可使用 `x-rustdesk-event-id` 去重。
- 渠道凭据不会在列表中回传。变更移动推送服务地址时请重新填写所需凭据。填写最终服务地址，确保请求无需经过重定向。
